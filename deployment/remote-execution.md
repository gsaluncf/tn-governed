Azure executes SQL, Polars, scalar processing, recipient verification and review queuing. An SSH control connection carries the model HTTP tunnel and bulk file transfers to the Runpod server. `remote_performance.py` selects the remote process launchers for the model stage and records the remote host and transport-source hashes in the measurement manifest. The calculation, model prompts and output verification use the benchmark modules.

Before each governed model session, one compressed archive transfers the native endpoint directory and its input/output experiment session directories. The source SQLite database stays on Azure. Paths and runtime configuration bytes remain the same on both hosts, preserving the configuration digest recorded by the client. The model runs as a fresh process with prompt caching disabled. After generation, one archive returns the model records and output-session state. Startup and staging remain outside the generation interval; the HTTP round trip is included in generation wall time, with inference reported from server measurements.

`TN_REMOTE_MODEL_CONFIG` names the JSON connection settings. This file contains the SSH host, port, identity-file path, remote binary/model paths, control-socket path and worker path. The SSH private key remains on Azure. Each model API key is supplied to the remote worker on SSH stdin.
